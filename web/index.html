Paper trading only

An LLM portfolio manager

AuraTrade is an investment agent whose current goal is to manage a $100,000 account and beat the S&P 500 over 10 years, after tax.

Once a month, code reads the market's trend and sets how much of the S&P 500 to own: 1.3x while the trend is up, 0.5x while it is down. Claude makes the judgement calls the rules can't: how to spread a fifth of the account across approved ETFs, and whether to lean the rest slightly more or less. It reads the account, the market data, the news and its own track record, and writes down every reason. Code checks every decision against hard limits before an order goes in, and a rules-only twin runs beside it, so Claude's value is measured, not assumed.

Who decides what

The split is the core of the design: judgement goes to the model, arithmetic and safety stay in code.

Claude decides

  • How the 20% satellite is spread over 13 approved ETFs: Nasdaq, small caps, value, quality, international, gold, bonds, managed futures, cash
  • Whether to shift the core's exposure by up to 0.2x, and only down when the rules say to hold less
  • A written reason for every change, and what it expects to happen
  • What to make of the regime, macro data and news

Code enforces

  • The trend, the volatility cap and the drawdown halt, so the core's rule level
  • Every target weight, share count and order price
  • Leverage only through a 2x S&P fund, never margin, with a stop at the broker
  • Each ETF at most 10% of the account; no leveraged or inverse funds in the satellite
  • Fail closed: on any doubt, never more risk; a failed decision holds: the rule level and last month's satellite

A month, and a day

  1. Every evening
    Ingest, journal, twin. ETF bars and macro data come in; the rules-only twin is played forward; the drawdown is checked.
  2. Month end
    The trend. The market's month-end value is read against its 10-month average; the volatility cap and the halt set the rule level.
  3. 08:45
    Portfolio Manager. On the first session of the month, Claude sets the satellite and the core's shift, with its reasons. No valid decision by noon means holding: the rule level and last month's satellite.
  4. 15:40
    Rebalance. Holdings more than 5 points off target are traded back to it: sales first, then buys, as limit orders.
  5. 09:35–16:00
    Stop guard. Every 5 minutes, code checks that the leveraged fund's stop at the broker covers every share.

Times are US Eastern. Every job first checks the market calendar. The trend flips about once a year, so most months change little.

How it works

The pipeline, step by step. Each step is a small job on AWS that runs on the New York clock, checks the market calendar first, and reports to a Telegram channel when something needs attention.

A dashboard inside the chat: MCP Apps

The dashboard tool uses MCP Apps, the protocol's UI extension (io.modelcontextprotocol/ui, the standard that grew out of MCP-UI). Instead of only text, the tool's result points to a ui:// page that the host, claude.ai or Claude Desktop, draws in a sandboxed frame beside the answer.

  1. The handshake. The page and the host talk JSON-RPC over postMessage: the page initializes, the host sends the tool's result and its light or dark theme, and the page reports its height.
  2. Data for the page, text for the model. The numbers ride in the result's structuredContent, which the host keeps out of the model's context; the model reads a short summary, the same answer clients without MCP Apps show.
  3. Self-contained. The page carries this site's own chart code inline, so inside the sandbox it loads nothing and fetches nothing.
  • A circuit breaker. A flood of calls switches the server off within the hour and sends a Telegram alert, so a stranger can't run up a bill or slow the trading jobs.
  • On the owner's machine, the same server runs over stdio with read-only tools on the database, the broker and the logs: the system's status, its jobs, the tax lots, one decision whole.

Tech stack

What each part is, and how it is used.

The brain

Claude Opus 5.5 through Anthropic's SDK: structured answers, tools for news, charts and its own record, prompt caching, and a hard 12:00 deadline.

The jobs

Python 3.13 in one container image, one AWS Lambda function per job, scheduled by EventBridge on New York time; the evening jobs run as a chain.

Broker and data

Alpaca for paper trading and market data (delayed consolidated bars, real-time IEX quotes); CBOE for the VIX, FRED for interest rates.

The memory

Neon Postgres for the account, the decisions and the journal; older prices archived as Parquet on S3, and a nightly backup.

Safety

Guardrails as pure functions in code, a single-writer lock on every order change, the stop resting at the broker, and a kill switch that blocks new risk but never an exit.

The MCP server

The official MCP Python SDK on AWS Lambda behind a function URL, speaking Streamable HTTP. Its dashboard uses MCP Apps, the MCP UI extension: an interactive page drawn inside claude.ai.

This site

Static pages on S3 behind CloudFront, served over HTTPS at auratrade.dev; its data is one file published each evening.

Infrastructure and CI

Every AWS resource defined in code with the AWS CDK; GitHub Actions lints, type-checks and tests every change before it merges.

Alerts

A Telegram bot for everything that needs a human, and healthchecks.io as the dead-man's switch if the watchdog itself goes quiet.

The trend dial

How much of the S&P 500 the core owns. A 2% buffer around the average keeps it from flipping on noise, and from selling, and paying tax, more than it must.

StateExposureHeld as
Up-trend1.3x70% S&P fund, 30% 2x S&P fund
Turbulent1.0x at mostVolatility above 25% a year: no leverage
Halted1.0x at most25% below the peak: the 2x fund sold the next day
Down-trend0.5x50% S&P fund, 50% T-bills

The core is 80% of the account; Claude's satellite is the other 20%.

Limits the model can't override

Guardrails are pure functions with full branch coverage. They run on every decision the model proposes, and anything outside them is clipped or rejected.

1.5xthe most S&P exposure the core can ever reach
±0.2xClaude's shift of the core, downward only when the rules say hold less
10%of the account at most in any satellite ETF
0margin: leverage only through the 2x fund
−30%stop at the broker on the 2x fund, raised monthly
−25%drawdown halt: no leverage until the trend turns up again or the account is back at its peak
  • Prices come from code. The model chooses weights; it never names a price.
  • The leveraged fund's stop always rests at the broker. No halt, kill switch or error path ever cancels it or blocks a sale.
  • On doubt, less risk. Missing data, a model error or a calendar mismatch can only hold or reduce exposure.

How it's judged

The rules were backtested under a test fixed in advance; the LLM can't be honestly backtested, so its value is measured forward against a rules-only twin, and every decision is logged.

Backtest: passed

1928–2026, after Israeli tax: +9.2% a year against +8.7% for the S&P held, a worst drawdown of 68% against 85%, and ahead in 69% of ten-year windows. A thin edge, from the long bear markets; since the rules were published, a tie.

The twin

The same rules on the whole account, simulated beside the real book every day. Whatever the LLM does shows up as the difference.

Scorecard

Each month's tilts and expectations are scored against what happened, before and after the estimated tax.

The test was written down before any data was read, and run once.
